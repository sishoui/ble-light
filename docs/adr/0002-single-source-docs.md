# 0002 文档文件名不带版本号，作废即删除

## 背景

lumen 留下 62 个 Markdown / 16,525 行，其中 27 个文件（7,261 行，占根文档 57.7%）标着「已作废」却仍在仓库里。同时并存 4 份协议文档、4 份测试向量、3 份规格、5 份验收文档，**14 个文件声称自己是「唯一真相」**，其中 5 个各自声称定义当前协议字节。`README.md` 直到最后还写着 v4 是当前版本。

后果是真实发生的：新会话读错文档、按已关闭的票继续干活、同一批测试数字在文档里有四个版本。

## 决策

**每个事实只有一个家，文件名不带版本号。**

| 事实 | 唯一归属 |
|---|---|
| 协议字节、命令码、State 布局 | `docs/protocol.md` |
| 领域术语 | `GLOSSARY.md` |
| 为什么这么定 | `docs/adr/NNNN-*.md` |
| 当前进度 / 下一步 | `docs/status.md`（≤60 行，原地重写） |
| 测试分层与接缝 | `docs/testing.md` |
| 验收项与证据 | `docs/acceptance.md` |

配套规则：

1. **禁止** `protocol-v2.md`、`spec-final.md`、`xxx-old`、`handoff.md`、`pending-tasks.md` 这类文件名
2. **作废即删除**，git 就是归档。需要对照历史时用 `git show <ref>:<path>`
3. 文档之间**只许指针，不许复述**。同一事实出现在两处 = 缺陷
4. `docs/status.md` 每轮结束**原地重写**，不追加历史段落
5. 发版打 tag（`v1.0.0`），版本身份不靠 commit message 和散文

## 后果

- 想读历史版本要会 `git show`，比翻文件多一步——这是刻意的摩擦
- `docs/` 文件数封顶在 10 个左右；新增文件需要先证明现有文件放不下
- 项目管理面板（`docs/map.json` + `npm run map`）提供另一种查历史的界面

## 备选

- **保留历史文档并加横幅**：lumen 试过，27 个文件 7,261 行的「已作废」噪音，失败。
- **每代协议新开文档**：这正是病因，否决。
